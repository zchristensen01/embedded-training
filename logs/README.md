# Logs

- `log.tsv` — every kata rep. date, module, variant, minutes, clean, note. Read by `make report`.
  `clean` means "compiled first try, no sanitizer findings" for a C module and "ran first try,
  no traceback" for a `*_py` one. The two are never averaged together: C1 is scored on the C
  rate alone, and `make report` prints them as separate tables.
- `splits.tsv` — phase breakdown per rep: design, write, compile, debug. Written by `make lap`.
  A Python rep records `run` where a C rep records `compile`, because there is nothing to
  compile. `write + compile` as a share of total is your C syntax fluency in one number, and
  `write + run` is the Python one. `make report` prints them apart, never combined.
- `ai-use.tsv` — one line every time you use AI. date, used_for, rule, note. Review it weekly.
  If this file is growing in week 8, the rules in PRACTICE_SYSTEM.md aren't being followed.
- `WEEKLY_REVIEW.md` — copy the block every Sunday.
- `rehearsal.tsv` — every behavioural take: date, story, seconds, rating, note. Written by
  `make rehearse`. Three takes rated 1 on three different days is a ready story.
- `bughunt.tsv` — every bug hunt: date, module, mutation kind, minutes, whether you found it.
  Written by `make hunt-done`. `make hunts` shows which kinds keep catching you out.
- `design-prompts/` — written answers to design prompts, with rubric scores. **Fill in the
  total** — `make progress` reads it, and an unscored answer counts for nothing.
- `architecture/` — written architecture drills, same rule about the total. A *different*
  rubric from the design prompts, out of the same 16 so one parser reads both.
- `PROGRESS.md` and `progress.json` — every capability scored against its evidence bar.
  **Generated by `make progress`. Do not edit them by hand** — an edit would be overwritten by
  the next run, and the number would be a claim rather than a measurement. Unlike the calendar
  these are *not* checked by `make check-generated`: they depend on deck box positions, which
  change every time you review, and checking them made CI unable to agree with any working tree.
  Regenerate them when you want the score current; the header says when it was last run.
- `.start_date` — created on day 1 so `make today` knows where you are:
  `date +%F > logs/.start_date`
- `.snapshots/` — copies of your own solutions, kept only so `make hunt` has something
  to mutate. Gitignored, like `src/`. Still disposable; just a slower bin.
